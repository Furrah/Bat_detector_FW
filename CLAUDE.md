# Bat detector — STM32G431 firmware

Handheld, battery-powered ultrasonic bat detector covering the 20–120 kHz echolocation band (common pipistrelle ~45 kHz; highest frequency that must be detected: 100 kHz). It's a learning project in analogue + digital electronics; the commercial benchmark is the Pipistrelle Mini (heterodyne, auto-tune, time expansion, spectrum display, microSD), and the aim is to beat it on capability at a competitive cost. V1 PCB works; the V2 board (4 layers) is built and the firmware is being ported to it (from Oct 2026).

- MCU: STM32G431CBT6 (LQFP48), 128 KB flash, 32 KB RAM
- Schematic: `bat_detector_circuit.pdf` (V2)
- Tools: STM32CubeIDE 2.1.1 + STM32CubeMX, HAL + DMA/DMAMUX, KiCad 10, LTspice
- Build: `make -C Debug all` with CubeIDE's bundled make and GCC on PATH: `C:/ST/STM32CubeIDE_2.1.1/STM32CubeIDE/plugins/com.st.stm32cube.ide.mcu.externaltools.make.win32_*/tools/bin` and `.../com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.*/tools/bin`. Flash/debug stays in CubeIDE.
  - The Debug makefiles are generated by CubeIDE. New source files and folders only appear in them after a build inside CubeIDE.
  - `main.c` has its own include-path list in `.cproject` (a per-file override). A header folder added at project level must also be added to main.c's list, or main.c won't find it. `.cproject` is gitignored.
- The Debug configuration compiles at `-Og` (since Oct 30). Don't go back to `-O0`: at 250 kHz the DSP interrupt overruns (101% load at `-O0`, 37% at `-Og`).
- Branches: `v2` holds the V2 port (from `dev`) with its bring-up instrumentation. `essential` (from `v2`, Nov 3) is the product code only: the debug link, stats, `Core/Diag`, the bring-up tests and USB removed, to make the project readable. `Docs/HOW_IT_WORKS.md` explains it.
- Design decisions and their reasoning are logged in `Docs/engineering_diary.md`.

## Rules for changing code

- CubeMX-generated files: only edit inside `/* USER CODE BEGIN */ … /* USER CODE END */` blocks. Anything outside is wiped when the .ioc is regenerated.
- Make incremental, targeted changes scoped to the function or module in question, with the rationale stated. No whole-file rewrites.
- RAM: 3.3 KB free (28.7 of 32 KB used, Nov 4). That includes a 2 KB stack, a 0.5 KB heap reservation, ~1 KB of PSRAM-ring interrupt code that runs from RAM, the recorder's 8 KB slot buffer, playback's 1 KB and the species classifier's 4.3 KB. No malloc, no large stack buffers.
- Flash: 80.3 KB of 128 KB used at `-Og`, ~15 KB of it the classifier (89.6 KB on `v2` with the debug link and USB, no classifier). Large constant tables belong in flash rather than RAM.
- Interrupt priorities: DMA2 Channel 1 (the PSRAM ring's burst interrupt) must be the only interrupt at priority 0; everything else at 1 or lower. `PsramRing_Start()` refuses to run otherwise (boot screen: "Ring: NVIC prio"). Diary entry 34.
  - CubeMX defaults a newly enabled peripheral interrupt to priority 0. It did that to SPI2's global interrupt (Nov 2); check every new interrupt's priority after generating.
  - `__disable_irq()` blocks priority 0 too. Keep masked sections in code that runs while the ring is busy to a few dozen instructions: a masked section that delays a burst's end stretches CE#. Bursts have ~3.5 µs of slack (entry 36).
- Lookup tables are generated into `Core/DSP/Tables/` by `python Tools/gen_dsp_tables.py`: the Hann window, FFT twiddles, FFT unpack rotation and NCO sine. Don't edit them by hand. It also makes the classifier's 128-point set. Rerun the script after changing `AUDIO_FFT_LENGTH`, `LUT_SIZE` or `CLS_FFT_LENGTH`; a static assert fails the build if a table is stale. Python 3 is installed.
- Check `arm-none-eabi-size` after changes that add buffers or tables. When reading the .map, skip the "Discarded input sections" list at the top: symbols there were garbage-collected and use no memory.
- Do not add the prebuilt CMSIS-DSP library: the static archive bakes in every twiddle table and overflowed flash by ~9 KB. The FFT is hand-rolled on purpose. If CMSIS-DSP is ever needed, use the source-only library so size-reduction defines work.
  - Its CubeMX packs (X-CUBE-ALGOBUILD, FP-SNS-STAIOTCFT) were removed on Nov 3. Unticking their components wasn't enough: the packs stayed attached in the `.ioc` (`Mcu.ThirdParty0/1`), and CubeIDE's stored CubeMX defaults in `.cproject` (the `build.inputs` string) still listed the library. So every Generate Code put `-l:libarm_cortexM4lf_math.a` back, and a fresh clone failed to link. Both are clean now. If a library ever reappears in the linker settings, check those two places.
- Buffer sizes, the sample rate and the FFT length come from `Core/Inc/pipeline_config.h` (`AUDIO_SAMPLE_RATE_HZ`, `AUDIO_BLOCK_SIZE`, `AUDIO_BUFFER_SIZE`, `AUDIO_FFT_LENGTH`, `AUDIO_LO_MAX_HZ`). Never hard-code them. Module constants such as `ADC_BUFFER_SIZE`, `DSP_BLOCK_SIZE` and `WF_SAMPLE_RATE_HZ` are aliases of it.
- Shared ISR state (ping-pong FIFO counters etc.) needs short critical sections (`__disable_irq()` / `__set_PRIMASK()`). For FFT block handoff, drop rather than corrupt.
- DSP correctness is verified by cross-checking against numpy `rfft` on captured raw samples. The capture tools are on `v2` (`capture.py fftcheck`); on this branch, a WAV recording is the raw ADC and can be analysed on the PC. Offer a numpy check when changing DSP code.
- Back analysis with numbers (GBP, noise, throughput, timing) and give honest trade-offs rather than reassurance.
- When a design decision is made, add an entry to `Docs/engineering_diary.md`: the decision, its context, the reasoning with numbers, alternatives considered, the outcome, and the lesson for future designs.
- When debugging peripherals, reason from register reads (`DMA1->ISR`, `CNDTR`, `CCR`, `DAC1->CR`, `DAC1->SR`, DMAMUX `CCR`) decoded to bit-field level.

## Hardware (v2)

- Mic: SPVA1A0LR5H-1 MEMS (rated to ~80 kHz) on J1. Front end: a single OPA365 non-inverting stage, fixed gain 1 + (39k + 100k)/1k = 140×, biased to mid-rail. No gain pot.
- At the ADC pin: 33 Ω + 1 nF (corner ~4.8 MHz). This is a charge reservoir for the ADC, not an anti-alias filter. Op-amp closed-loop bandwidth is ~360 kHz, so anything above Nyquist aliases.
- No analogue mixer: heterodyne is fully digital. TIM3 (V1's LO square wave) has no job on V2.
- SPI1: APS6404L 8 MB PSRAM, alone on the bus. Planned as the continuous pre-trigger ring buffer and the time-expansion source.
  - Above 33 MHz, reads must use Fast Read `0x0B`; plain Read `0x03` is limited to 33 MHz.
  - CE# may stay low for at most tCEM = 8 µs (refresh). At 42.5 MHz that limits DMA bursts to ~32 bytes.
  - Verified on hardware: ID 0D/5D and the address-line test pass. The polled `-O0` driver uses 8-byte bursts; CE# max measured 5.0 µs.
- SPI2: ILI9341 2.4" TFT + its on-module SD slot, shared. The display has its own CS on V2. SD MOSI/CLK go through 33 Ω. No touch controller is wired.
  - SD MISO (PB14) has no external pull-up; the internal pull-up is on (CubeMX, Nov 2, diary 42). Without it, a missing card floats MISO low and reads as "busy" (a 500 ms timeout) instead of "no card".
  - Use a card that fits the slot natively. A microSD in an SD adapter kept losing contact (Nov 2).
- SD card runs in SPI mode (G431 has no SDMMC). USB-C exposes the card via USB device MSC. FatFS and USB MSC must never access the card at the same time (needs a mutual-exclusion state machine).
- Power: system always runs from the 3.7 V LiPo (MCP73831 charger; USB only charges). There is no 5 V rail.
  - The MCP1700 LDO is always on. The S1 slide switch sits between the LDO output and the 3V3 rail.
  - No VBUS sense reaches the MCU, so USB attach has to be inferred from USB reset/suspend events.
  - J7 "BYPASS" shorts USB 5 V onto the battery node. Never fit it with a cell connected.
- Audio out: TS4990 BTL amp powered from the battery rail, gain ~1.5×, with a 2-pole RC low-pass (~6–10 kHz) on its input. STBY is on `AMP_EN`, and R9 (100k pull-down) keeps the amp off until firmware drives it high. The volume knob is read on an ADC pin and applied as digital gain in the DSP.
- RTC: internal. Y1 (32.768 kHz) is DNP on the current build, so the RTC runs from HSE/32 and loses time at power-off. VBAT comes from the always-on LDO output through R29 (1 kΩ). On the MCU sheet that net is labelled "VBUS", but it is not USB 5 V.
- Indicator LEDs: 680 Ω, ~2 mA. Design for 1–3 mA, not 20 mA.
- Volume pot VR1 (RK10J12E002L): its datasheet pinout is misleading, so the wiper isn't on the pin the footprint routes to PA5. V2 boards need a solder bridge to connect the wiper. Fix the symbol/footprint for V3.

## Firmware state (`essential` branch, Nov 2026; check against the code)

`Docs/HOW_IT_WORKS.md` explains the code: the signal path, the PSRAM ring, recording, playback, the detector, auto-tune, the boot sequence, the main loop and the interrupts, with Mermaid diagrams. Keep it in step when behaviour changes.

This branch is the product code only. The bring-up instrumentation is in the `v2` branch, and its files are in `Archive/`:

- the USB CDC debug link (`debug_link.c`, `Diag/diag_link.c`) and its PC tools (`Archive/Tools/capture.py`, `analyse_capture.py`, `diaglink.py`);
- the stats table and every Live Expressions timing or health counter (`dspCyclesMax`, `psramRingMaxSelectNs`, `dacLateBlocks`, `sdErrorCount`, `rec*`, `bat*Db`, ...);
- the `Core/Diag` library;
- the PSRAM pattern tests and the SD speed test.

To measure something (DSP load, CE# time, FFT against numpy), use `v2`, or port the one counter needed.

- **Audio path:** ADC→DSP→DAC, timer-triggered DMA with ping-pong buffers. `adc.c` calls one block callback (`ADC_SetBlockCallback`) per half buffer, after `PsramRing_PushBlock`. Start order in `main.c`: `DAC_Start()`, `ADC_Start()`, then `HAL_TIM_Base_Start(&htim2)`.
- **Sample rate:** exactly 250 kHz (TIM2 ARR 679). `main.c` stops in `Error_Handler` at start-up if the CubeMX TIM2 period doesn't match `pipeline_config.h`.
- **`dsp.c`:** digital heterodyne, per sample in `DSP_ProcessBlock`, no decimation.
  - Chain: −2048 → 10 kHz Butterworth high-pass biquad → ×`DSP_GAIN` (8) → mixer → two 8 kHz Butterworth low-pass biquads → × volume → +2048, clamp → `DAC_WriteBlock`. Each stage truncates to `int32_t`.
  - The mixer is a 32-bit phase-accumulator NCO indexing the 512-entry flash sine table (`phase >> 23`), with a Q15 multiply.
  - The high-pass output is squared and summed per block for the detector. The raw block goes to the FFT.
  - During playback the mixer and low-passes are skipped.
  - LO range 0–120 kHz (`AUDIO_LO_MAX_HZ`); the LO starts at 0 Hz until the knob is read.
  - DSP load (measured on v2): 37% at `-Og` without the ring, 45% with it writing, 66% writing and reading back to back. One block is 174,080 cycles.
- **`dsp_filters.c`:** Butterworth biquad low-pass/high-pass design and processing only. The notch filter and DC blocker are gone (never connected); they're in `v2`.
- **`dac.c`:** each block is copied into the half of the circular DAC buffer that the DMA isn't reading, chosen from `CNDTR`.
- **`fft.c`:** 1024 real samples packed into a 512-point complex FFT, Hann window, unpacked with the half-length real-FFT identity: 513 unnormalised linear-magnitude bins in `fftMagnitude[]`, with `fftMagnitudeReady`.
  - Window, twiddles and unpack rotation come from the flash tables. It builds at `-O2` via a `#pragma`; bit reversal uses `RBIT`. About 1.3 ms a frame (216k cycles at `-O2`, interrupts included; diary 39).
  - `FFT_AddSamples` (in the interrupt) drops blocks while a frame waits; `FFT_Process` runs in the main loop.
  - Verified against numpy `rfft` (6.8e-8 of the largest bin, Nov 2, on v2).
- **`waterfall.c`:** 240 columns over 0–125 kHz (bins 0–1 skipped, ~2.1 bins per column, peak-held between rows), thermal palette, hardware scroll (VSCRDEF/VSCRSADD in the afiskon driver), kHz ticks every 20 kHz. The axis is absolute: the FFT is of the raw ADC. `Waterfall_DrawAxis()` draws it once; `ui.c` owns the header line. `Waterfall_SetRange(-10, 20)` was calibrated on V1; recalibrate for the 140× front end.
- **`bat_detect.c`:** stage 1 of the bat-call detector (monitor only; the amp stays on).
  - Runs once per block on the 10 kHz high-pass energy, in linear energy (no `log10f`).
  - Tracks the noise floor: falls with a 250 ms time constant, rises with 4 s, 16 ms during a 0.5 s warm-up. The floor is frozen during a loud run, and learns again after 150 ms of one.
  - Pulses are 1–100 ms runs more than 12 dB above the floor. A pass starts on 3 pulses, each within 600 ms of the one before, and holds 2 s after the last.
  - LED0 = pass in progress; LED1 = a 50 ms flash per call during a pass.
  - Parameters: diary 30 and 44.
  - Known limit: finger rubs and typing (broadband ultrasound up to 40 dB above the floor) trigger it; it needs a tonality test (diary 44). It also misses quiet bats and calls under a loud steady tone.
- **`autotune.c`:** fed from the waterfall's rows (`Waterfall_GetRow`, 240 columns every 40 ms), with a per-column noise floor learnt between passes.
  - During a pass, each row with a call gives the column furthest above its floor, refined to ~0.1 kHz. The LO goes `AUTOTUNE_OFFSET_HZ` (1.5 kHz) below the median of the last 8 calls. It moves only for more than 2 kHz, at most once a second, and holds between passes.
  - Modes: hold PLAYBACK 0.8 s to switch manual (the knob) / auto ("AUTO 43.5kHz"). Starts in manual. Diary 45. Works on the bench with finger rubs; needs a field test.
- **`psram.c`:** boot-time reset (0x66/0x99) and ID check (0x9F; expects 0D 5D) only, polled with interrupts masked and bounded waits, at /8. `PSRAM_OK`, `PSRAM_ERR_ID`, `PSRAM_ERR_SPI`.
- **`psram_ring.c`:** continuous recording of the raw ADC into the PSRAM (diary 34–36). The last 16.8 s (16384 blocks of 512 bytes) are always kept.
  - From `PsramRing_Start()` (after `PSRAM_Init`, before the ADC) it owns SPI1.
  - Each block is 32 DMA bursts of 16 bytes on DMA2 Ch1 (RX) and Ch2 (TX). The RX transfer-complete interrupt raises CE# and starts the next burst. CE# measured 4.44 µs at most against the 8 µs tCEM. Don't go back to 32-byte bursts: reads reached 8.1 µs (entry 36).
  - The burst interrupt's code is `__RAM_FUNC`, the file builds at `-O2`, and its helpers are forced inline: 2.3–2.5 µs of CPU per burst (from flash at `-Og`, 4 µs, which overran the DSP). `DMA2_Channel1_IRQHandler` returns before `HAL_DMA_IRQHandler`. After touching the file, check the disassembly: `PsramRing_IRQHandler` should call only `PsramRing_StopDma` and the fault path (`PsramRing_StartBurst` is inlined).
  - `PsramRing_PushBlock` is called from `adc.c`. `PsramRing_ReadBlock` queues a read by block number (queue of 16); writes go before reads, and reads keep 64 blocks clear of the writer.
  - `PsramRing_Start()` refuses to run unless SPI1 is 8-bit at /4 with NSS pulses off, PB3–5 are High speed, and DMA2 Ch1 is alone at priority 0 (plain register checks in the file).
  - `PsramRing_SetPaused()` stops recording (reads still run). `PsramRing_GetWrittenBlocks()` is the newest readable block + 1. Block numbers carry on across a pause; `PsramRing_GetResumeBlock()` gives the first block after it, so a pre-trigger never joins audio from both sides of a playback.
- **`playback.c`:** time-expansion playback (diary 37). PLAYBACK (short press, on release) replays the last `PLAYBACK_SECONDS` (2 s) `PLAYBACK_EXPANSION` (10) times slower; press again to stop.
  - Linear interpolation at the full 250 kHz DAC rate, after the same 10 kHz high-pass. Replaces the heterodyne output; detector and waterfall stay live.
  - The ring is paused during playback. Two 512-byte slots: one plays while the next loads. The header shows "PLAY 10x  20s".
- **`sd_spi.c`:** SPI-mode SD driver on SPI2, polled through HAL (diary 38–40). FatFS R0.12c through `user_diskio.c`, with `_FS_TINY` on, LFN off and exFAT off.
  - Cards: FAT32 (FAT12/16 also mount) on MBR, SDHC ≤ 32 GB. Format with SD Card Formatter (32 KB clusters), not Windows. exFAT shows "SD: not FAT32".
  - Multi-sector writes are CMD25 with the ACMD23 pre-erase hint.
  - A failed read or write re-initialises the card and retries once. `user_diskio.c` clears ST's once-only init flag, so a failed card is retried on the next mount.
  - The SPI2 DMA path was tried and removed (missed start tokens, diary 40); it's in v2.0.0.
- **`recorder.c`:** WAV recording to SD on RECORD (diary 41–42).
  - Starts 5 s before the press (`RECORDER_PRETRIGGER_SECONDS`); a second press stops it; files stop at 600 s (`RECORDER_MAX_SECONDS`, 300 MB).
  - Files are `BATnnnnn.WAV` in the root (next number after the highest; never overwrites). Mono 16-bit PCM at 250 kHz, samples `(code − 2048) × 16`.
  - The header is 512 bytes (a 460-byte `JUNK` pad) so the audio stays sector-aligned. The first chunk is 7 blocks, then 8-block chunks on 8-sector offsets, so each `f_write` is one 8-sector write. Don't shrink the header to 44 bytes.
  - 16 slots of 512 bytes in its own static 8 KB buffer: one chunk is written while the next loads. Polled from the main loop ahead of the FFT, up to 20 ms per `Recorder_Poll`.
  - Every 2 s: `f_sync`, then the header's sizes go straight to the file's first sector with `disk_write` (no `f_lseek`). A power cut loses at most 2 s.
  - Stopping writes out the backlog ("REC saving"). If the ring overwrites unsaved audio, the recording stops ("REC: SD slow") rather than splicing. The card is mounted afresh at each start.
  - PLAYBACK is refused while a recording is open ("PLAY: busy"), RECORD during playback ("REC: playing"). The header shows "REC   1:23".
  - Measured on v2: slowest write 15.3 ms, slowest sync 6.1 ms; 8-sector writes 1.38× real time catching up, 1.93× caught up. Still to test: a 10-minute recording, a power cut (S1), recording straight after a playback.
  - `python -I Tools/check_raw.py D:\BAT00001.WAV` checks a recording on the PC: the header, and every sample a 12-bit code × 16.
- **`classifier.c`:** the species classifier on the board (diary 51–52; `Docs/CLASSIFIER_PLAN.md`, `Docs/CLASSIFIER_FINDINGS.md`). Runs on the board (the user, Nov 4).
  - **Known problem: false passes indoors.** In 3 minutes by day near the PC, with taps, it reported 17 passes ("BATSP", "NYCGRP", "FAINT", ...). They're made of 1–3 ms pieces at 15–35 kHz, several within 1–5 ms of each other at wandering frequencies (diary 52). The user paused rule work on this.
  - When the detector starts a pass, it reads the pass back from the ring in the main loop, from 2 s before it began, 4 blocks per poll in two 512-byte slots (as playback). It ends when the pass is over and it has caught up.
  - It stands aside while a recording is open or saving and during playback. More than 12 s behind, or across a ring pause, it ends the session and starts again on newer audio (`classifierSkips`).
  - `classifier_calls.c` (stages 1–3: 128-point frames, segmenter, features) and `classifier_species.c` (stages 4–6: shape groups, European rules, vote) are a HAL-free port of `Tools/classify.py` and `species.py`. Their constants are in `classifier_config.h`; keep them in step with the model.
  - Each reported sequence's verdict shows in the header for 5 s, in yellow ("PIPPIP 87%  9").
  - Faint-sweep verdicts ("FAINT", "PLESP", "BARBAR": long-eared bats, barbastelle) are neither shown nor logged (`CLASSIFIER_REPORT_FAINT` 0 in `classifier.h`): indoor noise and taps were named that way too easily (the user, Nov 4).
  - `CALLS.CSV` (`call_log.c`; `CALL_LOG_ENABLED`, on by default as the user chose) gets one line per *reported* pass, the verdict the header showed (~40 B). Detections it doesn't report never reach the card. `CALL_LOG_CALLS 1` adds a line per call (~100 B each), needed for `check_classifier_c.py --device`, but it grew ~50 KB in 3 minutes indoors, so it's off. Lines are buffered 512 B at a time: mount, append, close, so nothing is open when the recorder takes the card.
  - `classifierBlockCyclesMax` (Live Expressions): the most cycles one ring block of frames has taken. Real time is 174,080. Not measured yet.
  - `python -I Tools/check_classifier_c.py <WAVs or folders> [--bench]` builds the two HAL-free files with MSYS2 gcc (`C:/msys64/ucrt64/bin`) and compares them with the model call by call. `--device D:\CALLS.CSV D:\BAT00001.WAV` compares the board's log with the model on a WAV of the same pass.
- **`ui.c`:** the front panel: buttons (debounce, long press), knobs (ADC2 scan of LO pot, volume, V_BAT/2 every 10 ms), LEDs, the header line (including the classifier's verdict), waterfall rows with auto-tune, and the battery readout ("BAT" over "3.9", top right). Volume is square-law. The LO label is fixed at 13 characters so it clears the battery readout.
- **`boot_checks.c`:** SPI2 set-up (8-bit, NSSP off, PB13–15 High speed: "SPI2: config"), PSRAM reset/ID and ring start ("PSRAM: no reply", "Ring: NVIC prio", ...), SD mount (type and size, or why not).
- **`main.c`:** CubeMX init, then the modules, the display, the boot checks and the audio start. The loop is `UI_Poll`, `Recorder_Poll`, `Classifier_Poll`, `FFT_Process`, `UI_PollDisplay`.
- **USB:** removed on this branch (Nov 4). USB_DEVICE, the USB peripheral, CRS and HSI48 are off in CubeMX; they only served the debug link. The hardware is unchanged. `main.c`'s per-file include list in `.cproject` still names the USB and `Core/Diag` folders: harmless (GCC skips missing folders), tidy it with CubeIDE closed.
- **V2 port, still to do:** recalibrate `DSP_GAIN` and `Waterfall_SetRange` for the 140× front end.

Bugs already fixed — do not reintroduce:
- FFT unpack twiddle sign is `+2πk/N`.
- `DSP_Mixer` LUT index must be `phase >> 23` for the 512-entry (2^9) sine table. `>> 24` only addresses half the table and gives a near-DC oscillator, which caused speaker-to-mic acoustic feedback.

## Hard-won gotchas

- DMA start order: `DAC_Start()` → `ADC_Start()` → `HAL_TIM_Base_Start()`. Reversing it underruns on the first TRGO. (main.c currently starts TIM2 first; reconcile.)
- On the G4 the DAC underrun IRQ shares the `TIM6_DAC` vector. There is no `DAC1_IRQn`; enable it via CubeMX's combined TIM6/DAC interrupt option.
- SPI2 is shared by the display (CS PA8) and the SD card (CS PB2). `MX_GPIO_Init` leaves every CS low unless the pin's output level is set High in CubeMX, so deselect both before any SPI2 traffic. Keep all SPI2 users in main-loop context so they serialise.
- SD init needs ≤400 kHz. With APB1 at 170 MHz, SPI2's slowest clock (/256) is 664 kHz, so APB1 must be /2. APB timer clocks double when the prescaler isn't 1, so TIM2/TIM3 still run at 170 MHz.
- CubeMX's default SPI data size on G4 is 4 bits. Always set 8 bits explicitly.
- CubeMX generates SPI pins at `GPIO_SPEED_FREQ_LOW`. Use High / Very High for anything above ~20 MHz.
  - Hit on V2: SPI1 at 42.5 MHz on Low-speed pins hung waiting for RXNE. The master's receiver is clocked by SCK through the pad, and a Low-speed pad can't toggle at 42.5 MHz. High fixed it.
- CubeMX's default SPI "NSSP Mode" on G4 is Enabled. The SPI then idles SCK for 2 clocks after every byte to pulse its NSS pin, even with software NSS: 10 clocks per byte instead of 8 (20% slower). It pushed PSRAM bursts from 7.5 µs to 9.1 µs, over tCEM. Keep it Disabled on SPI1 and SPI2; `PsramRing_Start()` refuses to run if SPI1's `CR2.NSSP` is set. Diary entry 35.
- Code in ordinary SRAM (0x2000_0000) runs at ~2 cycles per instruction on the M4: instruction fetches and data share the system bus. Only CCM SRAM (0x1000_0000) is contention-free. Diary entry 36.
- The linker warns "LOAD segment with RWX permissions" because the ring's interrupt code runs from RAM. Expected; not a fault.
- Starting a debug session in CubeIDE rebuilds and flashes. Take "before" measurements before launching the debugger on new code.
- Flashing resets the MCU but not the SD card. A card left confused (e.g. by a failed transfer) can stop answering even CMD0 until it loses power: power-cycle with S1, or reseat the card. Seen twice on Nov 2 (diary 40).
- Don't expand an SPI `DR` register in the debugger's SFR view. The debugger's read pops the RX FIFO and can clear RXNE under the running code.
- On the G4 SPI, access `DR` as 8 bits for 8-bit frames. A 16-bit write packs and sends two bytes.
- GCC 14 treats a call to an undeclared function as an error. Removing a header include also means removing the calls that need it.
- If LSE is enabled with Y1 not fitted, `SystemClock_Config` times out and `Error_Handler` hangs with IRQs off. The board looks dead.
- USB on V2 enumerates in only one USB-C plug orientation (Oct 30). The other way round, Windows reports "Device Descriptor Request Failed", `USB->FNR` reads 0xC000 (D− high) and `DADDR` stays 0: D− isn't connected that way, probably a dry joint on J8 A7/B7. Use the working orientation until J8 is reflowed. Diary entry 31.
- CubeMX's CRS settings (CRS SYNC = USB_FS) write `HSI48CalibrationValue = 32`, and the field can't be edited. The G4's trim is 7 bits with 64 as the middle, so `v2`'s `main.c` `USER CODE SysInit` block puts it back to 64. `CRS->CR` should read 0x4060 before USB starts. (No USB on `essential`.)
- The RTC prescalers must match its clock source: (Asynch+1)(Synch+1) = f_RTC. CubeMX's 127/255 default is for 32.768 kHz; HSE/32 = 500 kHz needs 124/3999.
