# Bat detector — STM32G431 firmware

Handheld, battery-powered ultrasonic bat detector covering the 20–120 kHz echolocation band (common pipistrelle ~45 kHz; highest frequency that must be detected: 100 kHz). It's a learning project in analogue + digital electronics; the commercial benchmark is the Pipistrelle Mini (heterodyne, auto-tune, time expansion, spectrum display, microSD), and the aim is to beat it on capability at a competitive cost. V1 PCB works; the V2 board (4 layers) is built and the firmware is being ported to it (from Oct 2026).

- MCU: STM32G431CBT6 (LQFP48), 128 KB flash, 32 KB RAM
- Schematic: `bat_detector_circuit.pdf` (V2)
- Tools: STM32CubeIDE 2.1.1 + STM32CubeMX, HAL + DMA/DMAMUX, KiCad 10, LTspice
- Build: `make -C Debug all` with CubeIDE's bundled make and GCC on PATH: `C:/ST/STM32CubeIDE_2.1.1/STM32CubeIDE/plugins/com.st.stm32cube.ide.mcu.externaltools.make.win32_*/tools/bin` and `.../com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.*/tools/bin`. Flash/debug stays in CubeIDE.
  - The Debug makefiles are generated by CubeIDE. New source files and folders only appear in them after a build inside CubeIDE.
  - `main.c` has its own include-path list in `.cproject` (a per-file override). A header folder added at project level must also be added to main.c's list, or main.c won't find it. `.cproject` is gitignored.
- The Debug configuration compiles at `-Og` (since Oct 30). Don't go back to `-O0`: at 250 kHz the DSP interrupt overruns (101% load at `-O0`, 37% at `-Og`).
- Branches: `v2` holds the V2 port (from `dev`).
- Design decisions and their reasoning are logged in `Docs/engineering_diary.md`.

## Rules for changing code

- CubeMX-generated files: only edit inside `/* USER CODE BEGIN */ … /* USER CODE END */` blocks. Anything outside is wiped when the .ioc is regenerated.
- Make incremental, targeted changes scoped to the function or module in question, with the rationale stated. No whole-file rewrites.
- RAM: 1.7 KB free with the USB debug capture, the PSRAM ring and playback built in (31.0 KB used, including a 2 KB stack, a 0.5 KB heap reservation, 1 KB of PSRAM-ring interrupt code that runs from RAM, and playback's 1 KB of block buffers). `DEBUG_CAPTURE 0` in `debug_link.h` frees its 8 KB buffer. No malloc, no large stack buffers.
- Flash: 83.3 KB of 128 KB used at `-Og` (95 KB at `-O0` before the capture module). Large constant tables belong in flash rather than RAM.
- Interrupt priorities: DMA2 Channel 1 (the PSRAM ring's burst interrupt) must be the only interrupt at priority 0; everything else at 1 or lower. `PsramRing_Start()` refuses to run otherwise (boot screen: "Ring: NVIC prio"). Diary entry 34.
  - `__disable_irq()` blocks priority 0 too. Keep masked sections in code that runs while the ring is busy to a few dozen instructions: a masked section that delays a burst's end stretches CE#. Bursts have ~3.5 µs of slack (entry 36).
- Lookup tables are generated into `Core/DSP/Tables/` by `python Tools/gen_dsp_tables.py`: the Hann window, FFT twiddles, FFT unpack rotation and NCO sine. Don't edit them by hand. Rerun the script after changing `AUDIO_FFT_LENGTH` or `LUT_SIZE`; a static assert fails the build if a table is stale. Python 3 is installed.
- Check `arm-none-eabi-size` after changes that add buffers or tables. When reading the .map, skip the "Discarded input sections" list at the top: symbols there were garbage-collected and use no memory.
- Do not add the prebuilt CMSIS-DSP library: the static archive bakes in every twiddle table and overflowed flash by ~9 KB. The FFT is hand-rolled on purpose. If CMSIS-DSP is ever needed, use the source-only library so size-reduction defines work.
- Buffer sizes, the sample rate and the FFT length come from `Core/Inc/pipeline_config.h` (`AUDIO_SAMPLE_RATE_HZ`, `AUDIO_BLOCK_SIZE`, `AUDIO_BUFFER_SIZE`, `AUDIO_FFT_LENGTH`, `AUDIO_LO_MAX_HZ`). Never hard-code them. Module constants such as `ADC_BUFFER_SIZE`, `DSP_BLOCK_SIZE` and `WF_SAMPLE_RATE_HZ` are aliases of it.
- Shared ISR state (ping-pong FIFO counters etc.) needs short critical sections (`__disable_irq()` / `__set_PRIMASK()`). For FFT block handoff, drop rather than corrupt.
- DSP correctness is verified by cross-checking against numpy `rfft` on captured raw samples. Offer a numpy check when changing DSP code.
- Back analysis with numbers (GBP, noise, throughput, timing) and give honest trade-offs rather than reassurance.
- When a design decision is made, add an entry to `Docs/engineering_diary.md`: the decision, its context, the reasoning with numbers, alternatives considered, the outcome, and the lesson for future designs.
- When debugging peripherals, reason from register reads (`DMA1->ISR`, `CNDTR`, `CCR`, `DAC1->CR`, `DAC1->SR`, DMAMUX `CCR`) decoded to bit-field level.

## Hardware (v2)

- Mic: SPVA1A0LR5H-1 MEMS (rated to ~80 kHz) on J1. Front end: a single OPA365 non-inverting stage, fixed gain 1 + (39k + 100k)/1k = 140×, biased to mid-rail. No gain pot.
- At the ADC pin: 33 Ω + 1 nF (corner ~4.8 MHz). This is a charge reservoir for the ADC, not an anti-alias filter. Op-amp closed-loop bandwidth is ~360 kHz, so anything above Nyquist aliases.
- No analogue mixer: heterodyne is fully digital. TIM3 (V1's LO square wave) has no job on V2.
- SPI1: APS6404L 8 MB PSRAM, alone on the bus. Planned as the continuous pre-trigger ring buffer and the time-expansion source.
  - Above 33 MHz, reads must use Fast Read `0x0B`; plain Read `0x03` is limited to 33 MHz.
  - CE# may stay low for at most tCEM = 8 µs (refresh). At 42.5 MHz that limits DMA bursts to ~32 bytes.
  - Verified on hardware: ID 0D/5D and the address-line test pass. The polled `-O0` driver uses 8-byte bursts; CE# max measured 5.0 µs.
- SPI2: ILI9341 2.4" TFT + its on-module SD slot, shared. The display has its own CS on V2. SD MOSI/CLK go through 33 Ω. No touch controller is wired.
- SD card runs in SPI mode (G431 has no SDMMC). USB-C exposes the card via USB device MSC. FatFS and USB MSC must never access the card at the same time (needs a mutual-exclusion state machine).
- Power: system always runs from the 3.7 V LiPo (MCP73831 charger; USB only charges). There is no 5 V rail.
  - The MCP1700 LDO is always on. The S1 slide switch sits between the LDO output and the 3V3 rail.
  - No VBUS sense reaches the MCU, so USB attach has to be inferred from USB reset/suspend events.
  - J7 "BYPASS" shorts USB 5 V onto the battery node. Never fit it with a cell connected.
- Audio out: TS4990 BTL amp powered from the battery rail, gain ~1.5×, with a 2-pole RC low-pass (~6–10 kHz) on its input. STBY is on `AMP_EN`, and R9 (100k pull-down) keeps the amp off until firmware drives it high. The volume knob is read on an ADC pin and applied as digital gain in the DSP.
- RTC: internal. Y1 (32.768 kHz) is DNP on the current build, so the RTC runs from HSE/32 and loses time at power-off. VBAT comes from the always-on LDO output through R29 (1 kΩ). On the MCU sheet that net is labelled "VBUS", but it is not USB 5 V.
- Indicator LEDs: 680 Ω, ~2 mA. Design for 1–3 mA, not 20 mA.
- Volume pot VR1 (RK10J12E002L): its datasheet pinout is misleading, so the wiper isn't on the pin the footprint routes to PA5. V2 boards need a solder bridge to connect the wiper. Fix the symbol/footprint for V3.

|---|---|---|---|
| PA0 | ADC1_IN1 mic (`ADC_INPUT`) | PB0 | PSRAM CS (100k pull-up) |
| PA1 | ADC2_IN2 LO pot (RV1) | PB2 | SD CS |

## Firmware state (as of Sep–Oct 2026; check against the code)

- ADC→DAC DMA passthrough, timer-triggered, ping-pong buffering.
- `fft.c`: 1024 real samples packed into a 512-point complex FFT, Hann window, unpacked with the half-length real-FFT identity. Outputs 513 unnormalised linear-magnitude bins in `fftMagnitude[]`.
  - The window, twiddles and unpack rotation come from the flash tables.
  - `fftProcessCyclesAvg` / `fftProcessCyclesMax` time `FFT_Process`. Measured 2.14 ms per frame (5.77 ms with the old `cosf`/`sinf` unpack).
- `bat_detect.c` (Core/DSP): bat-call detector, stage 1 (monitor only; the amp stays on).
  - Runs once per block from `DSP_ProcessBlock`, on the energy of the 10 kHz high-pass output.
  - Tracks the noise floor, finds pulses (1–100 ms long, more than 10 dB above the floor), and triggers on 2 pulses within 600 ms, with a 2 s hold.
  - LED0 = bat pass in progress; LED1 = 50 ms flash per pulse. These replace V1's LO-band LEDs.
  - Live Expressions: `batEnergyDb`, `batFloorDb`, `batPulses`, `batTriggers`, `batNoiseRuns`, `batPresent`.
  - Parameter reasoning is in diary entry 30.
- `debug_link.c` (Core/Src; header in Core/Inc so dsp.c and the USB code can include it): USB CDC debug capture, built 2026-10-30.
  - The PC sends one byte: `I` info, `R` a raw 4096-sample snapshot, `E` / `S` start / stop one energy record per block. Replies are CRC-32 framed; the format is at the top of `debug_link.c`.
  - Hooks: `DebugLink_AddBlock` in `DSP_ProcessBlock`, `DebugLink_OnReceive` in `usbd_cdc_if.c` `CDC_Receive_FS`, `DebugLink_Poll` in the main loop.
  - PC side: `python -I Tools/capture.py info|raw|energy --label <note>` saves `Captures/*.npz`. `python -I Tools/analyse_capture.py <file.npz>` prints the analysis and writes a PNG: spectrum lines, noise, the detector's predicted input, energy periodicities, and an offline detector replay with a threshold sweep. Needs `python -m pip install pyserial numpy matplotlib` (installed).
  - Keep `DETECTOR` in `analyse_capture.py` in step with `bat_detect.c`; the replay reports if it disagrees with the board.
- `dac.c`: each DSP block is copied straight into the half of the circular DAC buffer that the DMA isn't reading, chosen from the DMA's remaining count (CNDTR). `dacLateBlocks` counts blocks that collided with the DMA; it should stay 0.
- `waterfall.c/.h`: built on the afiskon ILI9341 driver with VSCRDEF/VSCRSADD hardware scroll patched into the driver. Portrait native orientation, peak-hold accumulator (so short calls aren't lost between rows), thermal palette, bins 0–1 excluded, ticks every 20 kHz, LO frequency readout at the top. dB conversion happens here. `Waterfall_SetRange` was calibrated from measured dB values.
- `dsp.c`: digital heterodyne, per sample in `DSP_ProcessBlock`. There is no decimation: the output runs at the full 250 kHz.
  - Chain: −2048 → 10 kHz Butterworth high-pass biquad → ×`DSP_GAIN` (8) → `DSP_Mixer` → two cascaded 8 kHz Butterworth low-pass biquads → × volume → +2048, clamp to 0–4095 → `DAC_WriteBlock`.
  - `DSP_Mixer`: a 32-bit phase-accumulator NCO indexing the 512-entry flash sine table (`phase >> 23`), with a Q15 multiply.
  - The sample is cast back to `int32_t` between stages, so each stage truncates.
  - The high-pass output is also squared and summed per block for the bat detector. The raw input block goes to the FFT and the debug link.
  - During playback, the mixer and low-passes are skipped.
- Sample rate: exactly 250 kHz (TIM2 ARR 679), decided Oct 30. `main.c` stops in `Error_Handler` at startup if the CubeMX TIM2 period doesn't match `pipeline_config.h`.
- LO range 0–120 kHz (`AUDIO_LO_MAX_HZ`). The LO label is fixed at 13 characters (`LO: 120.0 kHz`) so it stays clear of the battery readout.
- DSP load: `adc.c` records the worst-case `DSP_ProcessBlock` time in `dspCyclesMax` / `dspLoadMaxPercent` (watch in Live Expressions). One block at 250 kHz is 174,080 CPU cycles. Measured 37% at `-Og` (~252 cycles/sample) without the PSRAM ring. With it: 45% while it writes, 66% while it also reads back to back (`verify`), because its burst interrupts preempt the DSP.
- ADC2 scans LO pot / volume / V_BAT/2 via DMA1 Ch3 (`ADC2_StartScan` / `ADC2_ScanReady` / `ADC2_Get`). `ADC_Init` stops if the CubeMX rank count changes.
- Volume: square-law digital gain (`DSP_SetVolume`). Battery voltage shows as two lines, "BAT" over "3.9", at the top right of the waterfall header.
- `psram.c` (Core/Drivers): register-level, interrupt-masked SPI1 driver.
  - Every burst has a 10 µs deadline and returns `PSRAM_ERR_TIMEOUT` instead of hanging.
  - Tests: walking-ones address-line test and a full 8 MB pattern test.
- `psram_ring.c` (Core/Drivers): continuous recording of the raw ADC into the PSRAM, verified on hardware 2026-10-30 (diary 34–36). The last 16.8 s (16384 blocks of 512 bytes) are always kept.
  - From `PsramRing_Start()` (after the boot tests, before the ADC) it owns SPI1. The polled `psram.c` driver is boot-only after that.
  - Each block is written as 32 DMA bursts of 16 bytes, on DMA2 Ch1 (RX) and Ch2 (TX). The RX transfer-complete interrupt raises CE# and starts the next burst. CE# measures 4.44 µs at most, reads included, against the 8 µs tCEM. Don't go back to 32-byte bursts: reads reached 8.1 µs (entry 36).
  - The burst interrupt's code is marked `__RAM_FUNC` (runs from RAM), and `psram_ring.c` builds at `-O2` via a `#pragma`. It costs 2.3–2.5 µs of CPU per burst; from flash at `-Og` it was 4 µs and overran the DSP. `DMA2_Channel1_IRQHandler` returns before `HAL_DMA_IRQHandler`.
  - `PsramRing_PushBlock` is called from the ADC callbacks in `adc.c`. `PsramRing_ReadBlock` queues a read by block number, and writes go before reads.
  - Live Expressions: `psramRingMaxSelectNs` (must stay below 8000), `psramRingOverTcem`, `psramRingLateBlocks` and `psramRingFaults` (must stay 0), `psramRingBlocks`, `psramRingReads`.
  - Timing diagnostics: `psramRingMinSelectNs`, `psramRingMaxEntryNs` (CE# low to interrupt start), `psramRingMaxIsrNs` (CPU per burst), `psramRingBursts`. Write 1 to `psramRingResetStats` to restart them.
  - Verify with `python -I Tools/capture.py verify --count 50`: debug link `M` reads the last snapshot back from the ring and the PC compares it bit for bit. It fails while playback has the ring paused.
  - `PsramRing_SetPaused()` stops recording (reads still run); `PsramRing_GetWrittenBlocks()` gives the newest readable block + 1.
- `playback.c` (Core/DSP): time-expansion playback, verified on hardware 2026-10-30 (diary 37). PLAYBACK replays the last `PLAYBACK_SECONDS` (2 s) from the ring `PLAYBACK_EXPANSION` (10, in `pipeline_config.h`) times slower; press again to stop.
  - Linear interpolation at the full 250 kHz DAC rate, after the same 10 kHz high-pass as the heterodyne. Replaces the heterodyne output while active (`DSP_ProcessBlock`); detector and waterfall stay live.
  - The ring is paused during playback and resumes when it ends. Two 512-byte slots: one plays while the next block loads.
  - Live Expressions: `playbackUnderruns` (should stay 0). The display shows "PLAY 10x  20s" in place of the LO readout.
- `sd_spi.c` (FATFS/Target): SPI-mode SD driver on SPI2, verified on hardware 2026-11-02 with a 16 GB SDHC card (diary 38). FatFS R0.12c is wired up through `user_diskio.c` with `_FS_TINY` on, LFN off and exFAT off.
  - Cards: FAT32 (FAT12/16 also mount) on an MBR partition table, SDHC of 32 GB or less. Format with the SD Association's SD Card Formatter (32 KB clusters, 4 MB-aligned), not Windows. exFAT, which every card over 32 GB ships with, doesn't mount: the boot screen shows "SD: not FAT32".
  - Only single-sector transfers have run so far. The CMD25/CMD18 multi-sector paths are untested.
- Boot checks run before the audio starts:
  - PSRAM: hold RECORD at power-up for the full 8 MB test (~35 s).
  - SD: hold PLAYBACK at power-up for a 256 KB write/read speed test. It leaves `SDTEST.BIN` on the card. Measured W666 R648 kB/s; its 64-byte `f_write` calls make every transfer single-sector.
- V2 port, still to do:
  - Disconnect TIM3 (V1's LO). Keep `tim3_lo.c/.h` in the project; the technique is in `Docs/timer_waveform_output.md`.
  - `ili9341_touch.*` is V1-only: it hardcodes `hspi1`, PB4 and PA10, which are now the PSRAM bus. Its include and call are disconnected; keep the files.
  - Recalibrate `DSP_GAIN` and `Waterfall_SetRange` for the 140× front end.
  - Drop the LO offset in `waterfall.c` `BinToDisplayFreq`. The FFT is of the raw ADC, so the axis is absolute; it only reads correctly today because `Waterfall_SetLOFrequency(0)` is the only call.

Bugs already fixed — do not reintroduce:
- FFT unpack twiddle sign is `+2πk/N`.
- `DSP_Mixer` LUT index must be `phase >> 23` for the 512-entry (2^9) sine table. `>> 24` only addresses half the table and gives a near-DC oscillator, which caused speaker-to-mic acoustic feedback.

## Hard-won gotchas

- DMA start order: `DAC_Start()` → `ADC_Start()` → `HAL_TIM_Base_Start()`. Reversing it underruns on the first TRGO. (main.c currently starts TIM2 first; reconcile.)
- On the G4 the DAC underrun IRQ shares the `TIM6_DAC` vector. There is no `DAC1_IRQn`; enable it via CubeMX's combined TIM6/DAC interrupt option.
- SPI2 is shared by the display (CS PA8) and the SD card (CS PB2). `MX_GPIO_Init` leaves every CS low unless the pin's output level is set High in CubeMX, so deselect both before any SPI2 traffic. Keep all SPI2 users in main-loop context so they serialise.
- SD init needs ≤400 kHz. With APB1 at 170 MHz, SPI2's slowest clock (/256) is 664 kHz, so APB1 must be /2. APB timer clocks double when the prescaler isn't 1, so TIM2/TIM3 still run at 170 MHz.
- CubeMX's default SPI data size on G4 is 4 bits. Always set 8 bits explicitly.
- CubeMX generates SPI pins at `GPIO_SPEED_FREQ_LOW`. Use High / Very High for anything above ~20 MHz.
  - Hit on V2: SPI1 at 42.5 MHz on Low-speed pins hung waiting for RXNE. The master's receiver is clocked by SCK through the pad, and a Low-speed pad can't toggle at 42.5 MHz. High fixed it.
- CubeMX's default SPI "NSSP Mode" on G4 is Enabled. The SPI then idles SCK for 2 clocks after every byte to pulse its NSS pin, even with software NSS: 10 clocks per byte instead of 8 (20% slower). It pushed PSRAM bursts from 7.5 µs to 9.1 µs, over tCEM. Keep it Disabled on SPI1 and SPI2; `PsramRing_Start()` refuses to run if SPI1's `CR2.NSSP` is set. Diary entry 35.
- Code in ordinary SRAM (0x2000_0000) runs at ~2 cycles per instruction on the M4: instruction fetches and data share the system bus. Only CCM SRAM (0x1000_0000) is contention-free. Diary entry 36.
- The linker warns "LOAD segment with RWX permissions" because the ring's interrupt code runs from RAM. Expected; not a fault.
- Starting a debug session in CubeIDE rebuilds and flashes. Take "before" measurements before launching the debugger on new code.
- The build string `capture.py info` prints is `debug_link.c`'s compile time, so it only changes when that file is recompiled. Use the uptime it prints to tell whether the board has restarted.
- Don't expand an SPI `DR` register in the debugger's SFR view. The debugger's read pops the RX FIFO and can clear RXNE under the running code.
- On the G4 SPI, access `DR` as 8 bits for 8-bit frames. A 16-bit write packs and sends two bytes.
- GCC 14 treats a call to an undeclared function as an error. Removing a header include also means removing the calls that need it.
- If LSE is enabled with Y1 not fitted, `SystemClock_Config` times out and `Error_Handler` hangs with IRQs off. The board looks dead.
- USB on V2 enumerates in only one USB-C plug orientation (Oct 30). The other way round, Windows reports "Device Descriptor Request Failed", `USB->FNR` reads 0xC000 (D− high) and `DADDR` stays 0: D− isn't connected that way, probably a dry joint on J8 A7/B7. Use the working orientation until J8 is reflowed. Diary entry 31.
- CubeMX's CRS settings (CRS SYNC = USB_FS) write `HSI48CalibrationValue = 32`, and the field can't be edited. The G4's trim is 7 bits with 64 as the middle, so `main.c`'s `USER CODE SysInit` block puts it back to 64. `CRS->CR` should read 0x4060 before USB starts.
- The RTC prescalers must match its clock source: (Asynch+1)(Synch+1) = f_RTC. CubeMX's 127/255 default is for 32.768 kHz; HSE/32 = 500 kHz needs 124/3999.

## Next up

- V2 order:
  1. V1 features running on V2. Done.
  2. PSRAM bring-up. Done; the full 8 MB test is still to run once.
  3. SD bring-up. Done (Nov 2): mount, write and read verified, including a PC check of `SDTEST.BIN`. Next: a sustained write test under recording load.
  4. RAM reclaim (done Oct 30), then the DMA-driven PSRAM ring buffer (verified Oct 30), then WAV recording to SD.
  5. Time-expansion playback from PSRAM on PLAYBACK. Version 1 built (fixed 10×, last 2 s). Next: start at the detector's last bat pass; a knob-set factor.
- Amplifier gating ("squelch"): switch `AMP_EN` on only while bats are detected.
  - Stage 1 (the monitor-only detector) is built; tune it in the field first.
  - Stage 2: drive `AMP_EN` from it, with a fade, amp off at zero volume, and forced on during playback.
  - The squelch-off (always-on) control is deferred.
- Recording architecture: SD writes can stall 100–250 ms (up to 125 KB at 500 kB/s), so PSRAM writes must be driven from the ADC ISR side. One ISR-driven SPI1 engine owns the PSRAM; the SD writer and the playback prefetch queue read requests to it.
  - Single-sector writes measured 666 kB/s at boot with nothing else running: 1.33× headroom, too thin to rely on. Choose the writer's transfer size from a sustained test under recording load (DSP and ring interrupts at 45–66%, FFT and waterfall in the main loop, display sharing SPI2), not from the boot test (diary 38).
- Finish the DSP chain: bandpass around the 1–2 kHz output, float throughout to avoid inter-stage truncation, and wire in the notch filter. It is initialised in `DSP_Init` but not connected in `DSP_ProcessBlock`, and `dsp_filters.h` hasn't been reviewed yet.
- Time-expansion mode: capture a detected call from PSRAM and play it back slowed down. The record button writes the PSRAM pre-trigger data to SD, followed by the live stream.
- WAV header formatting compatible with bat-ID software.
- Battery gauge accuracy: the reading is ratiometric to VDDA, which sags once the MCP1700 drops out near empty. That needs VREFINT, which is on ADC1, the audio ADC.
- Gain range switching or AGC.
- At 250 kHz, recording streams 500 kB/s to PSRAM and SD, and the PSRAM holds 16.8 s of history.
